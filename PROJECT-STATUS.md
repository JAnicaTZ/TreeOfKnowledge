## 1. What TREE Is

**Tree of Knowledge (TREE)** is an independent logic-based reasoning project originating from academic work in mathematical logic begun in 2002 and reintroduced for the age of Explainable AI.

TREE is intended to make formal reasoning explicit and inspectable.

Its responsibility is to help answer:

> **Does this conclusion logically follow from the declared facts and rules?**

TREE does not independently:

* establish legal or organizational authority;
* authorize consequential actions;
* issue executable permissions;
* prove that a downstream action occurred;
* certify the correctness of facts supplied by an external source.

Reasoning is not authorization.

## 3. Current Technical Direction

A bounded synthetic reference architecture is being discussed around four independent responsibilities:

| Layer         | Responsibility           | Question                                                                                            |
| ------------- | ------------------------ | --------------------------------------------------------------------------------------------------- |
| 🌳 TREE       | Reasoning                | Does the conclusion follow from the declared facts and rules?                                       |
| ⚖️ OMNIX      | Decision admissibility   | Is this exact action admissible under the authority and conditions that exist now?                  |
| 🛡️ Fidacy    | Bounded enforcement      | Can an allowed decision be converted into a constrained, short-lived or single-use execution grant? |
| 🔗 SignalLink | Provenance and integrity | What records were produced, how are they linked, and have they remained intact?                     |

The intended separation is:

> **Reasoning ≠ authorization**
> **Authorization ≠ execution**
> **Execution ≠ provenance**
> **Provenance ≠ substantive correctness**

No layer should silently absorb or redefine another layer’s responsibility.

## 5. What the Synthetic Test Demonstrated

The synthetic test represented the following proposed sequence:

> **TREE → OMNIX → Fidacy → Synthetic Executor → SignalLink**

Within that simulation:

* a synthetic TREE record represented a supported reasoning result;
* a synthetic OMNIX record represented an `ALLOW` decision;
* a synthetic Fidacy record represented a bounded single-use grant;
* a synthetic executor represented consumption of that grant;
* SignalLink linked the resulting identifiers and digests;
* a deliberately changed event produced a different digest;
* the mutation was detected.

This demonstrated the internal fluency of the proposed contract and the detection of a changed preserved event.

It did **not** invoke the native TREE, OMNIX or Fidacy runtimes.

It did **not** demonstrate production interoperability among those independent systems.

## 6. Proposed TREE Interface Boundary

The proposed TREE boundary includes:

### Proposed input

* scenario or request reference;
* exact proposition or query;
* declared facts and assumptions;
* applicable rule-set identifier and version;
* logical vocabulary and syntax;
* required domain or universe information;
* TREE engine and evaluator version.

### Proposed output

* stable `reasoning_record_id`;
* deterministic content digest;
* conclusion state such as `SUPPORTED`, `REFUTED` or `UNDETERMINED`;
* normalized and inspectable input representation;
* explicit reasoning or evaluation trace;
* references to the facts, assumptions and rules used;
* detected conflicts, unsupported elements and limitations;
* engine version and evaluation timestamp.

### Important implementation distinction

Each proposed field is intended to be mapped individually to the existing TREE implementation as:

* **EXISTS NATIVELY**
* **DERIVABLE**
* **REQUIRES ADAPTER**
* **NOT YET IMPLEMENTED**

The proposed interface should not be described as a native current capability until that mapping and implementation have been verified.

## 7. When TREE Should Remain Closed or Undetermined

At minimum:

* logical input is malformed or ambiguous;
* a required rule-set version is missing;
* syntax or a logical construct is unsupported;
* required domain information is unavailable;
* premises conflict in a way the selected logic cannot safely resolve;
* the requested proposition and produced record do not match;
* a required deterministic record cannot be generated or verified;
* internal evaluation or validation fails.

TREE may report whether a conclusion follows.

TREE does not convert a logical conclusion into a claim that an action is authorized, admissible or executable.

## 8. Current Collaboration State

At the date of this document:

* TREE remains an independent project;
* architectural discussion is active;
* the TREE reasoning boundary is documented but requires implementation mapping;

* SignalLink’s provenance and integrity work is independently documented in its repository;

Public listing of any person or organization should require explicit consent and an accurate description of scope.

Conversation membership, profile visibility, enthusiasm or silence should not be interpreted as proof of participation or consent.

## 9. Next Bounded Steps

The immediate priorities are:

1. map every proposed TREE interface field to the existing implementation;
2. identify the smallest adapter or export mechanism required;
3. confirm each independent system owner’s boundary;
4. agree on canonical synthetic record formats;
5. have each independent system emit its own test record;
6. recompute every digest independently;
7. repeat the mutation test using independently produced artifacts;
8. publish PASS or FAIL without upgrading the claim language;
9. document one realistic path toward scientific evaluation, a pilot or responsible licensing.

No additional architectural layer should be added unless it removes more uncertainty than it creates.
